## The delta that actually mattered

Same shape as both predecessors: exactly ONE section of the codebase was stale —
the persona's `### The harness now has its OWN cross-session messaging` block,
titled to the 2.1.224 → 2.1.232 window.

**The load-bearing argument is again untouched.** A native session-to-session
message still leaves no trace in the AI Maestro ledgers, so a governance act
delivered that way still did not happen as far as the fleet's record goes. What
changed in this window is *delivery honesty*, which is a different axis and is
exactly the kind of improvement that invites the wrong inference.

### 1. Four silent-failure modes closed (2.1.235 → 2.1.238) — DELIVERY, not AUTHORITY

A send to a session that refuses inbound (`crossSessionInbound: "refuse"`) now
reports `refused` instead of a false success; an inbox that drops a message
(rate limit, full queue) now tells the sender; an over-large message and a
burst that would overflow the recipient's inbox are both refused up front
rather than reported sent.

Written into the persona **with its non-implication**, because the persona
already asserts elsewhere that *"the absence of an error is not evidence of
permission"* (line ~1211), and these fixes make absence-of-error a *better*
signal — of transport only. A forbidden governance act sent natively still
succeeds, still returns no error, and still writes no ledger entry. The
asymmetry is unchanged; only the transport reporting improved.

### 2. Discovery widened, and its blind spot became visible (2.1.234, 2.1.240)

`ListAgents` now lists live teammates — before this a reachable teammate simply
did not appear — and tells a session its own name. Separately it now says when
the account's session list was too long to check completely.

The second half is the useful one and is written as the same MAY that
RGAQCQN6 applied to the `offline`/`cloud` labels: an absent peer may be
unlisted rather than gone, so a clean listing is not proof of absence, exactly
as `online` was never proof of reachability.

### 3. The channel reached Windows (2.1.240)

Cross-session messaging is now available on Windows, so the channel spans every
machine the owner runs. The USER's 2026-08-20 deny-invariant is written into
each agent workdir's `.claude/settings.local.json` and is OS-independent, so it
binds on Windows too — but an *unregistered* workdir is now reachable on three
platforms instead of two, which widens the population the surrounding paragraph
already calls out.
